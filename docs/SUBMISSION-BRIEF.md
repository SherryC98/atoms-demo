# Atoms Demo 简要说明

> **一句话介绍**：Atoms Demo 能把一句自然语言需求变成可交互的网页应用，并支持继续修改、换风格、查看历史版本和独立预览。

在线体验：[https://atoms-demo-gamma.vercel.app/](https://atoms-demo-gamma.vercel.app/)

本地运行：`npm install && npm run dev`。环境变量和 Supabase 初始化方式见项目根目录的 `README.md`。

## 1. 实现思路

我把核心流程拆成一条可观察的流水线：

`用户需求 → 生成计划 → 生成代码 → 安全校验 → 必要时自动修复 → 保存版本 → 沙箱预览`

模型负责理解需求、生成计划和完整 HTML；确定性的程序负责鉴权、限流、校验、持久化和预览隔离。前端展示 `Planning / Building / Validating / Fixing / Done` 等真实阶段，每个阶段都对应实际发生的请求，而不是装饰性的假进度。

生成结果是单文件 HTML。服务端使用 AST 解析检查结构和外部资源，替换模型提供的 CSP；通过校验后，页面才会进入不含同源权限的 iframe。若首次校验失败，系统会把错误交还模型修复一次；第二次仍失败则停止。首次生成失败时不保存坏代码；增量修改失败时不会替换当前预览，用户仍可继续使用修改前的版本。

开发和测试使用 Claude；需求边界、架构、安全策略和验收标准由我确定。线上改用 DeepSeek，以控制公开演示的调用成本。模型调用统一封装在服务端，可按需替换。

## 2. 三项关键取舍

### 2.1 先保证结果可用，再追求生成速度

我选择“生成—校验—自动修复”的闭环。它比直接展示模型输出多了一段等待时间，但能避免把截断、非法或不能运行的代码交给用户。目前页面能显示生成、检查和修复等阶段，但在耗时最长的生成阶段，用户还看不到更细的进展和等待时间。

### 2.2 用部分生成自由换安全可控

模型生成的页面不会直接拿来展示。我会先检查页面是否完整、引用的外部资源是否可信，再把它放进一个与主页面隔离的预览区。这样会限制少数依赖特殊资源的应用，但能避免有风险或失控的代码直接影响用户和主页面。

### 2.3 先降低试用门槛，再补完整账号体系

首版采用匿名身份，用户无需注册即可生成、修改和保存；Supabase RLS 保证只能访问自己的项目。用户清理浏览器数据后，原项目无法找回；当前又没有定期清理机制，长期公开运行会产生无主数据并占用存储空间。

## 3. 当前完成程度

### 已完成

- 首次生成、增量修改、换风格，以及失败后的同操作重试。
- 多项目历史、项目内版本快照与版本回退。
- Preview / Code 切换和独立预览页。
- 匿名身份、Supabase 持久化、RLS 数据隔离。
- HTML 结构校验、CSP 注入、iframe 沙箱和一次自动修复。
- 小时、每日和全局三级原子限流，异常时默认拒绝。
- 比基础功能更进一步的异常链路测试：生成失败重试、修复成功、二次修复失败且坏代码不落库。

### 本次有意控制的范围

- 未做逐 token 的 SSE 流式输出，当前采用按真实请求推进的阶段反馈。
- 未做正式账号、跨设备找回、公开分享和多人协作。
- 未做匿名项目的数据保留期限和定期清理任务。
- 生成应用内部只保留当前会话状态，不开放同源存储或任意后端连接。

### 当前已知风险

一轮对话需要依次写入用户消息、生成结果和当前版本，目前还不是同一个数据库事务。中途故障可能留下不完整记录。生成失败不会覆盖当前版本，但数据库写到一半的一致性风险仍未解决。

### 验证情况（2026-09-23）

完整用例和通过标准见 [验收测试用例](./ACCEPTANCE-TEST-CASES.md)。

- **生成与交互**：人工走通需求输入、页面生成和实际操作，待办应用可正常增删任务。自动测试因生成超过 180 秒而超时，同场景人工检查通过；功能可用，耗时仍有波动。
- **连续修改**：人工检查了继续修改、换风格、历史记录和版本恢复，原有功能能够保留。
- **失败处理**：自动模拟生成失败和修复失败，5 项检查全部通过；坏代码不会覆盖当前版本。
- **基础质量**：35 项自动检查和生产构建通过；还剩 22 个类型规范问题，另有 3 项浏览器自动检查尚未启用。

## 4. 如果继续投入时间

1. **P0｜核心可用性与数据一致性**：把多次数据库写入改为事务；定期清理过期匿名项目；处理生成超时和取消。同时清理 Lint、启用真实模型回归测试，并记录耗时、失败率和调用成本。
2. **P1｜改善长时间等待的体验**：在现有阶段条上增加细分进度、已等待时间和取消入口。若接入 SSE，只显示简短进度或纯文本代码，Preview 仍在检查通过后开放；修改失败时明确提示已保留上一版本。
3. **P2｜账号与资产沉淀**：增加可选登录、跨设备找回、可控的公开分享，再根据真实协作需求评估多人编辑。
